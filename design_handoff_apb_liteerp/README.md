# LiteERP 接入 APB：样式交付包 v1.0

日期：2026-10-20。接收方：LiteERP 开发组。主方案：**APB 中控中的独立 ERP 模块，保留 APB 外壳，ERP 只绘制内容区**。这是基于现有代码的接入方案；最终入口还没有由用户明确指定，因此也列出 iframe 和盒端差异。

可以直接采用这里的 CSS、token 和组件结构；样例 JS 只演示交互。**本包已完成样式交付，不表示 ERP 已在 APB 注册、已连业务接口或已上线。** 本次没有修改 LiteERP 仓库，没有改变 APB 运行时代码，也未部署。

## 1. 视觉方案

延续 APB 的“深色顶栏＋暖灰工作台＋红色主操作＋白色台账”。不用另一套品牌导航，避免进入 ERP 后像换了系统。

| 用途 | 值 | 规则 |
|---|---|---|
| 主操作 | `#d41920`；hover `#b1151b` | 红色主按钮，每个操作区一个主动作 |
| 顶栏／主标题 | `#1c1917` | 顶栏由 APB 管，不由 ERP 重画 |
| 正文／次要文字 | `#292524` / `#78716c` | 次要文字不能承担唯一错误说明 |
| 页面／容器 | `#fafaf9` / `#ffffff` | 容器靠细边框区分，不堆阴影 |
| 分隔线 | `#e7e5e4` | 细线，不给每个字段加卡片 |
| 输入边框／焦点 | `#8c817a` / `#b1151b` | ERP 扩展，改善识别；焦点外框 2px、offset 3px |
| 成功 | `#166534` / 底 `#e9f5ee` | 已完成等明确结果 |
| 警告 | `#92400e` / 底 `#fef3e2` | 暂停、资料待确认、陈旧数据 |
| 错误 | `#991b1b` / 底 `#fee9e9` | 明确失败；同时写原因与处理办法 |
| 信息 | `#0369a1` / 底 `#e6f4fa` | 处理中、一般提示 |

上表为阅读快照；开发使用 token，不复制色值到各页。主源是 APB `platform/app/static/admin.css`；扩展主源是本包 `extension-tokens.json`。

- 字体：系统字体，优先苹方／微软雅黑，不加载外部字体。单号、设备号、技术数据采用等宽字体，金额采用等宽数字、右对齐。
- 字号：标题 22px，分区 16px，正文 14px，表格 13px，说明 12px；正文行高 1.6。
- 形状：控件 7px、面板 12px 圆角。状态可用小胶囊；状态文字必须可见。
- 间距：4／8／12／16／24／32px；正常面板内边距 16px，页面间隔 24px。
- 控件：桌面 38px，小屏至少 44px；忙碌保留按钮宽高。复选框 24px，标签可点击。
- 图标：新模块统一使用一种线性 SVG 图标，16／20px、stroke 1.5–2；从 LiteERP 已有维护库选用，不混入多套风格。图标非必要时省略；图标按钮给中文 accessible name。
- 仅浅色；高对比模式尊重系统，不强制锁死颜色。禁止把“背景变黑”当作已完成深色适配。

## 2. 页面结构与尺寸

```text
APB 顶栏（账号、环境、时间）                    高 56
APB 主导航 204 │ 业务 / LiteERP                 外边距 24
              │ 订单管理                 主操作
              │ 模块子导航
              │ 筛选：关键词 / 状态 / 日期
              │ 选择范围与结果说明
              │ 订单表格（局部横向滚动）
              │ 显示范围与分页
```

中控内容最大 1480px。760px 以下现有 APB 侧栏变 70px，ERP 的表单变单列、工具栏换行；页面外边距 16px。ERP 内容不再自行加 204px 左偏移或 56px 顶偏移。

表格、详情、录入使用同一视觉语言：

| 页面 | 推荐结构 |
|---|---|
| 订单／客户／库存列表 | 页面标题、筛选、结果数、语义表格、分页；不加无意义统计卡片 |
| 订单详情 | 订单基础资料、部件列表、APB 生产状态、业务记录；复杂编辑走独立页面 |
| 创建／编辑 | 顶部说明；基本资料→业务资料→备注；尾部保存／返回；最大宽度 760px |
| 数据报表 | 单位、时间范围、数据截至时间显式；表格与下载权限一致 |
| 异常处理 | 常驻原因、失败环节、保留内容、下一步；不能只给一条红色 toast |

纵向让页面自然滚动；宽表格局部横向滚动，有提示与可见滚动条。不能裁掉备注、错误或底部保存。详情对话框有独立滚动、Escape、显式关闭和焦点恢复；生产中多部件的长详情优先独立路由。

## 3. 组件约定

| 组件 | 可直接使用的 class / 结构 | 必须配套的行为 |
|---|---|---|
| 根容器 | `[data-apb-erp]` | 所有 ERP 内容和 overlay 都在此内 |
| 按钮 | `.apb-erp-btn`，`data-variant="primary"` | 主次区分；禁用有理由；请求忙碌禁止重复 |
| 字段 | `.apb-erp-field` + `.apb-erp-input` | label、帮助与错误关联；必填写明 |
| 表单 | `.apb-erp-form` / `.apb-erp-formgrid` | novalidate；输入保留；首错聚焦 |
| 搜索 | `.apb-erp-search` / `.apb-erp-clear` | 清除恢复焦点；IME；300ms 防抖；旧结果作废 |
| 表格 | `.apb-erp-tablewrap` / `.apb-erp-table` | caption / th scope；分页；列值单位；独立操作 |
| 选择 | `.apb-erp-checkbox` | 当前页选择、半选、数量；变更筛选清空并说明 |
| 状态 | `.apb-erp-badge` + `data-tone` | success / warning / danger / info / 默认中性，均有文字 |
| 提示 | `.apb-erp-notice` + `data-tone` | 重要错误持久显示；成功 polite live region |
| 数据摘要 | `.apb-erp-kv` 的 dl / dt / dd | 缺失显示“未知”；不误填 0 或成功 |
| 流程 | `.apb-erp-tree` | 上下节点、每步文字、暂停原因；没记录≠通过 |
| 对话框 | `dialog.apb-erp-dialog` | showModal，聚焦与归还、背景 inert、可关闭 |
| 空状态 | `.apb-erp-empty` | 无数据／无匹配／无权限／失败各自文案 |

原生 select 是明确选择：与现有 APB 一致，弹出菜单由操作系统绘制，不能承诺跨系统像素一致。日期示例用显式 `YYYY-MM-DD` 文本路径；多选设备、客户远程检索等复杂控件，沿用 LiteERP 自己维护的无障碍组件，主题映射本包 token，不把普通 select 强行改成不完整的 combobox。

## 4. 状态、中文与数据格式

- **ERP 订单状态和 APB 生产状态分列。**“已保存／已接单”不代表完成打印；每个部件、每次 execution 都保留各自结果。
- 金额示例 `1,280.00`，表头写“元”；实际存储用后端定义的最小货币单位或 decimal，不用浮点相加算账。不同币种不能仅加同一个 ¥ 符号。
- 日期 `2026-10-20`；事件时刻 `2026-10-20 10:32:08（北京时间）`。日期字段不转时区，时间戳显式转 Asia/Shanghai。
- 尺寸 `210 × 297 mm`、纸重 `80 g/m²`、数量加单位；长编号可复制，未知不能变成空白或默认值。
- Flow 详情按订单→部件→执行→节点展开。显示选中与未选中的规则、实际卡点、未执行原因，不能由 ERP 猜测执行轨迹。
- 五框 metadata 分别展示 MediaBox / CropBox / TrimBox / BleedBox / ArtBox，保留显式、继承、默认、缺失、异常来源；区分原稿和处理结果。必要时分页展示不同页，保留 Rotate/UserUnit。具体尺寸规则以 APB 手册／执行合同为准。
- 暂停作业的 rerun 是 APB 授权动作；是否可重跑、版本、保护部件均读 APB 回执，不由 ERP 改状态模拟。

## 5. 必须覆盖的页面状态

| 状态 | 用户看到什么 | 接入要求 |
|---|---|---|
| 首次加载 | 正在读取，稳定容器 | 不伪造进度百分比 |
| 正常 | 记录、范围、更新时间 | 当前筛选可恢复 |
| 首次为空 | 尚无订单＋允许的创建入口 | 不和请求失败混淆 |
| 筛选无结果 | 没有匹配＋清除筛选 | 保留查询内容 |
| 读取失败 | 失败原因／请求编号＋重试 | 保留条件；无堆栈或秘钥 |
| 只读／权限不足 | 范围说明与允许的返回 | 后端拒绝写入；不靠隐藏按钮鉴权 |
| 正在保存 | 原表单、忙碌按钮 | 防重，禁止并发覆盖 |
| 保存失败 | 字段错误或摘要 | 保留用户输入与上下文 |
| 版本冲突 | 资料已更新，保留编辑 | 重读／对比；不能静默覆盖 |
| 断线／陈旧数据 | 最近确认时间，状态未确认 | 不将缓存展示为实时 |
| 结果未知 | 操作可能已受理，待核对 | 查回执，不能立即重试打印／收费 |

## 6. 开发组采用步骤

1. 先打开样例与截图，确认接入的是中控内容槽；如果实际采用盒端或 iframe，按 INTEGRATION.md 的对应契约处理。
2. 拷贝 `assets/`；根加 `data-apb-erp`，两份 CSS 在宿主样式之后加载。业务组件统一使用该 token／class，禁止散写全局样式。
3. Vue/React 可封装为自己的共享组件，保持相同 DOM 语义和状态；不得引入会影响宿主的 reset/preflight 或全局主题覆盖。
4. 根据真实接口完成权限、分页、请求取消、保存与回执；按交互约定验收。`preview/` 的数据和 JS 不带入生产。
5. 给 APB 组提交内容入口、静态资产路径、权限能力、实际 API／状态字典、回退办法和验收记录；本包里的建议路径不是已实现接口。

本包范围内可直接交接。正式集成前需明确的业务接点见 [INTEGRATION.md 第 5 节](INTEGRATION.md#5-接线前由双方确认的接口清单)，无需为样式开发先配置门店或打印设备。
