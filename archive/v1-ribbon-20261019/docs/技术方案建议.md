# LiteERP Web 版 — 技术方案建议

## 1. 结论

| 层 | 建议 | 理由 |
|---|---|---|
| 后端 | **Python 3.12 + FastAPI + SQLAlchemy 2 + Alembic** | 业务主要是单据 CRUD + 统计报表，Python 开发效率高；FastAPI 自动生成接口文档（OpenAPI），前后端可并行开发；团队已倾向 Python |
| 数据库 | **PostgreSQL 16** | 金额用 `NUMERIC(14,2)` 精确计算；报表类 SQL（分组汇总、窗口函数、按月统计）能力强；Ubuntu 上安装维护简单 |
| 前端 | **Vue 3 + TypeScript + Vite + TDesign Vue Next + vxe-table** | TDesign 正是 linyeah.com 使用的组件库，品牌色设为 `#e8424a` 即得到统一的红色系；vxe-table 支持分组表头、底部合计、右键菜单、虚拟滚动、单元格编辑，最贴近旧版 DevExpress 表格 |
| 部署 | **Ubuntu 24.04 + Nginx + Gunicorn/Uvicorn（systemd）**，或 Docker Compose | Nginx 托管前端静态文件并反向代理 `/api`；数据库每日 `pg_dump` 备份 |

> 如果团队主力是 Java/C#，可将后端替换为 Spring Boot 或 ASP.NET Core（旧版很可能是 .NET WinForms + DevExpress，C# 团队迁移成本最低）。前端方案不受影响。

## 2. 本次交付的静态原型（`web/`）

- 纯 HTML/CSS/JS，无依赖、无需构建，`nginx` 直接托管或本地双击 `web/index.html` 即可演示。
- 覆盖旧版 6 个功能区（前台/生产/财务/客户/报表/系统）约 60 个功能页面，字段与旧版截图一致，数据为内存模拟数据（刷新即恢复）。
- 用途：**需求确认 + 界面评审 + 字段清单**。正式开发时页面按模块迁移到 Vue 组件：原型中的列定义（`groups/columns`）可直接转换为 vxe-table 列配置，`js/data.js` 的数据结构就是数据库表设计的初稿。

## 3. 建议的系统架构

```
浏览器 (Vue3 + TDesign + vxe-table)
   │  HTTPS
Nginx ── /           → 前端静态文件 (dist/)
     └─ /api/*       → Gunicorn + Uvicorn workers (FastAPI)
                          │
                          ├─ PostgreSQL（业务数据）
                          ├─ Redis（可选：会话、缓存、打印/推送队列）
                          └─ 文件存储（客户文件、附件：本地目录或 MinIO）
```

后端模块划分（与功能区对应）：`auth`（员工、角色、权限）、`customer`（客户、联系人、分组价、协议价）、`order`（工作单、明细、流程转单、审核）、`finance`（结算、预存/IC 卡、零收、一般收支、转账、销账、期末结账）、`report`（只读统计 SQL / 物化视图）、`system`（经营项目、生产流程、会计科目、运行参数、打印样式、导入）。

## 4. 旧版功能迁移到 Web 时需要另行处理的点

| 旧版能力 | Web 方案 |
|---|---|
| IC 卡读卡器（卡片发行/选老客户-读卡） | 优先改为**手机号/会员码/二维码**；必须用读卡器时，用 Web Serial / WebUSB（Chrome）或一个本地小代理程序 |
| 打印工单/小票（打印样式） | 服务端用 HTML 模板生成 → 浏览器打印；小票机可用 ESC/POS 网络打印或本地打印代理 |
| 「文件」字段指向本机文件夹 | 改为上传附件到服务器 / NAS 目录，工单里保存链接 |
| 收款码（智多结算） | 对接微信/支付宝服务商接口，生成动态码 + 支付回调自动结算 |
| 多门店（门店：0-本店） | 数据库所有业务表带 `store_id`，权限按门店隔离 |
| 审核后不可修改 | 后端强校验（不仅前端置灰），并记录操作日志 |

## 5. 数据迁移

请提供**旧系统的数据库备份**（比 exe 更有用；旧版多为 SQL Server 或 Access）。我们将：
1. 反向分析表结构，与原型的数据结构做字段映射；
2. 编写一次性迁移脚本（Python），把客户、员工、经营项目、价格、历史工单、结算/预存余额导入 PostgreSQL；
3. 用「客户结余统计」「营业日报」等报表对新旧系统数据做核对。

## 6. 建议的开发顺序

1. **基础**：登录/员工/角色权限、客户分组、经营项目、生产流程（系统模块）
2. **核心闭环**：客户资料 → 新建工单 → 流程转单 → 收款结算 → 审核（前台 + 生产）
3. **资金**：预存/IC 卡、零收、一般收支、转账、销账、客户对账、期末结账（财务）
4. **报表**：营业日报、收支汇总、客户排行等
5. **数据迁移 + 并行试运行 + 切换**
